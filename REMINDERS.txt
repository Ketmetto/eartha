3. CONTENT-SECURITY-POLICY HEADER — done
   django-csp added (config/settings/prod.py and staging.py). Policy is
   'self' by default, with explicit allowances for what the frontend
   actually loads: Firebase (Google sign-in) and Google Maps (address
   autocomplete) script/connect origins, Google Fonts for style/font.
   Inline <script> blocks across apps/web/templates/web/*.html now carry
   a per-request nonce (nonce="{{ request.csp_nonce }}") instead of being
   allowed by 'unsafe-inline'.

   One accepted tradeoff: style-src still allows 'unsafe-inline', because
   the templates use plain style="..." attributes throughout (~80 of
   them), not just <style> blocks — nonces don't cover the attribute
   form, and converting all of them to a stricter scheme wasn't in scope
   here. CSS injection is meaningfully lower-severity than script
   injection, so this was a deliberate call, not an oversight.

   Originally verified only statically (grepped every template + JS file
   for external resource origins against the policy) since no browser was
   available to click through and watch for console violations — and that
   gap turned out to matter: the CSP broke the Django admin (django-unfold
   theme) on the next real check. Unfold is built on Alpine.js, which
   evaluates its x-data/x-on directives through a mechanism CSP's
   script-src treats as eval — needs 'unsafe-eval' to function at all,
   which the original policy didn't have, silently breaking nearly every
   interactive admin element (sidebar, dropdowns, tables) while leaving
   plain HTML bits like a raw search form still working. Fixed via
   base/middleware.py's AdminCSPMiddleware, which appends 'unsafe-eval'
   to script-src for /admin/ only (staff-only path) rather than loosening
   it site-wide — verified via response headers (curl), not a real
   browser, so still worth an actual click-through of the admin once
   there's a browser available. The Google sign-in popup flow on the
   public site is the other piece that's still unverified live.
