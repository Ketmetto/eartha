================================================================================
NEW ENDPOINTS
================================================================================

POST /api/v1/auth/register/
  → Now automatically sends verification email

GET /api/v1/auth/verify-email/?uid=<uid>&token=<token>
  → Verifies email, returns {"detail": "Email verified successfully."}

POST /api/v1/auth/resend-verification/
  Body: {"email": "user@example.com"}
  → Resends verification email (always returns 200 to prevent enumeration)

================================================================================
HOW IT WORKS
================================================================================

1. User registers → RegisterView calls services.send_verification_email()
2. Celery task sends email with uidb64 + token link
3. User clicks link → frontend calls GET /verify-email/?uid=...&token=...
4. Backend validates token, marks EmailAddress.verified = True
5. User can now do verified-only actions

================================================================================
FRONTEND INTEGRATION
================================================================================

After registration, show: "Check your email for a verification link."

The verification link should point to a frontend route like:
  /verify-email?uid=<uid>&token=<token>

That page should immediately call:
  GET /api/v1/auth/verify-email/?uid=<uid>&token=<token>

Then show success or error based on the response.

================================================================================
SECURITY NOTES
================================================================================

- Token expires after PASSWORD_RESET_TIMEOUT (default 3 days in Django)
- Token is invalidated if user changes email
- Resend endpoint always returns 200 to prevent email enumeration attacks
- Social users are auto-verified by allauth (Google/Apple already verified them)
